# Options

*Last updated: 2026-09-07*

Everything you can change, and where. Three places hold configuration: the app (once, at
launch), the button, and the app list on the Beacon page.

## In the app: `BeaconConfiguration`

Passed to `Beacon.configure(_:)` once at launch. The first four are required.

| Field | What it is | Default |
|---|---|---|
| `app` | `AppIdentity`: name, bundle identifier, version, build, and the git `commit` the build came from | required |
| `organizationName` | Named in the privacy notice the tester agrees to, so it says who can read the report rather than "the team" | required |
| `currentReporter` | A closure returning who is signed in as a `Reporter` (account id, display name, contact), or `nil` when nobody is | required |
| `transport` | Where the in-app sheet sends reports: `GitHubIssueTransport` (direct, the tester's own token), `RelayTransport` (a service you run), `LocalBundleTransport` (saved on the device, nothing sent), or `FallbackTransport` chaining two. On the Claude-only path pass `LocalBundleTransport` | required |
| `index` | The app map (`BeaconIndex`) behind the "which part of the app" picker; generated by `beacon-index` | `nil` — the picker offers only "not sure" and "something new" |
| `settings` | A closure returning your settings as `SettingEntry` values; pass secrets with `isRedacted: true` so they are counted but not shown | none |
| `hostNotes` | Anything else you want on every report, as `SettingEntry` values | none |
| `fileTreeRoots` | Folders whose names and structure may be listed (never contents), each with a depth and entry cap | none |
| `hostSecrets` | Strings you know are secret, read at call time, for the final sweep over the report text | none |
| `logTailLineCount` | How many lines of Beacon's own log ride along | 400 |
| `allowsScreenRecording` | Whether the record button is offered. Off is right for an app that shows other people's private data | `true` |
| `maximumRecordingSeconds` | Longest recording | 180 |
| `consentStore` | Where the tester's acceptance of the privacy notice is remembered | `UserDefaults` |
| `reportArchiveDirectory` | Where every report is written on the device before sending, so a failed send never loses one | Application Support / *app name* / Beacon / reports |

Settings, log, folders, recording and secrets apply to the in-app sheet. The Beacon page
carries only what fits in a link; see [What is collected](what-is-collected.md).

## The button: `BeaconInbox` and `BeaconInboxButton`

```swift
let beacon = BeaconInbox(page: pageURL, repository: "your-org/harbour")
BeaconInboxButton(beacon, title: "Report a problem", area: nil)
```

| Field | What it is |
|---|---|
| `page` | The Beacon page link. Keep it in your app's configuration, in one place |
| `repository` | `owner/name` of the repository fixes are made in. Sent with every report so the pickup routes it without guessing |
| `title` | The button's label. Localizable |
| `area` | The part of the app this button lives in, prefilled on the form. Pass it from a screen-specific button so the tester needn't say |

`beacon.url(area:)` gives you the link itself, if you would rather open it your own way
(a web view, a share sheet, a QR code on a kiosk).

### What the link carries

`app`, `bundle`, `version`, `build`, `commit`, `repo`, `os`, `osVersion`, `device`,
`arch`, `locale`, `tz`, `appearance`, `textSize`, `reporter`, `area`. Empty values are
left out rather than sent blank. A link that carries `version` locks the app choice on the
page.

## On the page: the app list

The Beacon page keeps a list of the apps it serves. Each entry has:

| Field | What it is |
|---|---|
| `name` | What testers see in the picker |
| `platform` | `macOS` or `iOS`, for the board |
| `repository` | `owner/name`, where the pickup files issues and makes fixes |
| `folder` | Where the source lives on the machine that runs the pickup |
| `tracker` | `github` — reports become issues and are worked there; `board` — reports stay on the page and are worked in place |

To add an app or change its tracker, ask the Claude session that published your page to
write the entry; the page needs no republish.

## The pickup

How often reports are picked up, and whether fixes are made unattended or only proposed,
is set in the pickup prompt (`Triage/PICKUP.md`) and the policy it follows. Defaults: a
watching session reacts within a minute; a scheduled task on your Mac runs when you start
it or on the schedule you give it; the GitHub workflow runs on weekday mornings; fixes are
made and merged when the [policy](what-happens-to-a-report.md) allows, and proposed as a
pull request otherwise.
